Demo, lessons and next steps

Live product

  • Website (Amplify): https://main.d2rkhtb7c0k5r7.amplifyapp.com/
  • Admin page: https://main.d2rkhtb7c0k5r7.amplifyapp.com/admin
  • Source code: https://github.com/ndthuy21/aurel-restaurant

The admin password is not published in this report; the presenter signs in on their own device. Dish names, prices, brand and address are sample data, so do not enter real customer information when trying the demo.

Demo video

Watch on YouTube · Team FantasticFive video “Dự án AWS Nhóm FantasticFive”, posted by Huỳnh Trí Nhân on 24/11/2026 (about 4 minutes 21 seconds according to the group’s report). It shows the customer pages, the contact and reservation forms, and the admin screen for managing the menu.

Suggested demo script

  1. Introduce the problem and open the architecture diagram.
  2. Menu: search, filter and page through the 100 dishes loaded from the API.
  3. Reservation form: send a valid request, then a wrong body to show the backend validation.
  4. Admin: sign in, open the pending request and change its status.
  5. Create a test dish with an image upload and check it on the menu page.
  6. Show CloudWatch: request count, 4xx and 5xx, logs and alarms.
  7. Questions: SES sandbox, admin MFA, quotas and the proposed email queue.

Common problems and fixes

SymptomLikely causeWhat to do
Browser shows a CORS error after deploymentFrontendOrigin is still https://pending.invalidRedeploy the backend with the real frontend origin
Menu is empty or the app cannot reach the APIAPI_BASE_URL or NEXT_PUBLIC_API_BASE_URL is missing or ends with a slash; NEXT_PUBLIC_* values are fixed at build timeCorrect the variables and start a new Amplify job
/admin/* returns 401 after signing inAn ID token was sent, or the access token (valid for 1 hour) expiredSign in again; the BFF must forward the access token
A reservation is saved but no email arrivesSES is in the sandbox and the recipient is not verifiedVerify the address or use the mailbox simulator
The Amplify job failsWrong Node version or missing variablesRead the build log, use Node 22 and the variable table
Resources remain after deleting stacksRetain policy on the table, buckets and repositoryFollow the clean-up page
Font error reported on a Windows machineFonts and symbols that depend on the device may lack glyphsEmbed Noto for Vietnamese, check NFC/NFD, replace symbols with SVG. Not yet re-tested on Windows
Documentation commits still trigger a buildThe pipeline follows the branch and may not honor skip markersStop jobs that change only documentation; keep the report repository separate from the app

Lessons learned

  • Write down every output of a stack right after creating it; later steps depend on them.
  • Keep the deployment package bucket separate from the media bucket.
  • Test the failure paths (401, 400) as well as the happy path.
  • State the limits honestly (SES sandbox, no WAF, no load test) instead of hiding them.

Next steps

  • Email outbox with SQS and a dead-letter queue, then SES production access.
  • MFA for the admin, and AWS WAF in front of the API.
  • A load test and a point-in-time recovery drill.
  • SNS notifications for the four alarms.
